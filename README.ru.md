> [!IMPORTANT]
> PiUI 0.2.0 — developer preview. Основная и проверенная платформа — Windows. Пакеты для Linux собираются, но контроль жизненного цикла нативных агентов проверен только на Windows; macOS — экспериментальная сборка. Релиз подписан и умеет обновляться, только если это сказано в его описании; иначе сборка не подписана и никогда не проверяет обновления. PiUI не является OS sandbox. ## Возможности PiUI

- **Чат с агентами, которыми вы уже пользуетесь.** Один интерфейс чата для Codex, Claude Code, Pi, Hermes и Prime Agent: выбор харнеса → модели → уровня рассуждений из собственного каталога харнеса, потоковая активность, диффы, одобрения прямо в ленте, очередь сообщений со steer и follow-up, slash-команды и поиск по чату. Каждый харнес сам хранит вход, модели, инструменты, одобрения и историю; PiUI не добавляет свой agent loop или клиент провайдера и никогда не читает и не хранит учётные данные.
- **Claude Code — только по вашей подписке.** PiUI запускает установленный `claude`, убирает переменные с API-ключами и облачными провайдерами, отказывает при любом входе, кроме подписки Claude, держит fast mode выключенным и останавливает сессию, если она сообщает о платном extra usage.
- **Пайплайны.** Визуальный редактор мультиагентных систем: шаги-агенты, маршрутизаторы, вызовы модели и скрипты; связи результата, маршрута, сообщений, наблюдения и делегирования; шаблоны, входные данные запуска, лимиты раундов ревью, проверки и ассистент, который только предлагает изменения. См. [переносимые файлы систем](docs/SYSTEM_FILES.md).
- **Запуски.** Холст запуска с состоянием каждого шага, живой активностью, результатом, диалогом, входными данными, попытками и расходом токенов шага, а также действия оператора: одобрить, отклонить, запустить заново с шага, отменить, повторить.
- **Автоматизации.** Разовые, интервальные и недельные расписания, которые запускают сохранённый пайплайн, пока PiUI открыт. Каждое расписание включается отдельно. См. [запуски по расписанию](docs/SCHEDULED_RUNS.md).
- **Всё локально.** Без аккаунта, облака и телеметрии. Харнесы сами общаются со своими провайдерами. Доверие к проекту позволяет агентам работать с файлами папки в пределах разрешений чата и никогда не выдаётся за sandbox. Запуск с `--safe-mode` открывает PiUI без расширений и агентов.

## Поддерживаемые харнесы

| Харнес | Проверенные версии | Примечания |
| --- | --- | --- |
| Codex (app-server) | 0.147.x – 0.157.x | Более новые версии помечаются как непроверенные и не запускаются. MCP-формы показываются карточками одобрения. |
| Claude Code | 2.1 или более поздняя 2.x | Только вход по подписке Claude: запустите `claude` в терминале и выполните `/login`. |
| Pi | установленный CLI `pi` | Источник истины для истории Pi — его JSONL. |
| Hermes | 0.21.0 | Через интерфейс ACP. |
| Prime Agent | 0.9.2, 0.9.3 | |

В «Настройки → Харнесы» видно, что PiUI нашёл на компьютере, какие версии установлены и что ещё нужно настроить.

## Установка

### Windows 10/11 (рекомендуемый способ)

1. Установите хотя бы один харнес и войдите в него его собственными средствами.
2. Откройте [релизы PiUI](https://github.com/CrazyAngelm/PiUI/releases) и выберите **v0.2.0**.
3. Скачайте `PiUI_0.2.0_x64-setup.exe` и `SHA256SUMS.txt`.
4. Проверьте контрольную сумму, запустите установщик (для текущего пользователя, без прав администратора) и откройте **PiUI** через меню «Пуск».

```powershell
Get-FileHash .\PiUI_0.2.0_x64-setup.exe -Algorithm SHA256
Get-Content .\SHA256SUMS.txt
```

Хеш из `Get-FileHash` должен совпадать со строкой установщика в `SHA256SUMS.txt`. Если в описании релиза сказано, что сборка не подписана, Windows может предупредить о неизвестном издателе: сначала проверьте контрольную сумму или [соберите приложение из исходников](#сборка-из-исходников). Портативный `PiUI_0.2.0_windows_x86_64.exe` работает без установки.

### Linux (x64)

Скачайте `PiUI_0.2.0_amd64.deb` (установка: `sudo apt install ./PiUI_0.2.0_amd64.deb`) или `PiUI_0.2.0_amd64.AppImage` (сделайте файл исполняемым и запустите) и проверьте его командой `sha256sum --check --ignore-missing SHA256SUMS.txt`. Пакетам нужен WebKitGTK 4.1 (Ubuntu 22.04 или новее). Контроль жизненного цикла нативных агентов на Linux пока не проверен, поэтому харнесы там отмечены как непроверенные.

### macOS (экспериментально)

Если в релизе есть `PiUI_0.2.0_universal.dmg`, он работает на Mac с Apple Silicon и Intel. Сборка подписана ad-hoc и не нотаризована: при первом запуске откройте её через правый клик → **Открыть**.

### Обновление

Если релиз публикует ленту обновлений, в «Настройки → О программе» появляются **Проверить обновления**, описание изменений и **Загрузить и перезапустить**. PiUI спрашивает подтверждение, проверяет загрузку по ключу подписи, встроенному в вашу версию, останавливает идущие чаты и шаги пайплайнов так же, как при выходе, устанавливает обновление и запускается снова. **Проверять обновления автоматически** выключено, пока вы его не включите. Иначе скачайте новый релиз и установите его поверх текущего. В обоих случаях чаты, пайплайны и настройки сохраняются, а история харнесов остаётся у самих харнесов.

## Первый запуск

1. Запустите PiUI и выберите **New chat**. Выберите харнес, модель и уровень рассуждений, затем отправьте сообщение.
2. Для работы с файлами нажмите **Add project…** и проверьте запрос доверия к этой папке.
3. Откройте **Pipelines**, чтобы начать с шаблона, **Runs** — чтобы следить за пайплайном, и **Automations** — чтобы запланировать его.

Не пишите в одну сессию одновременно из PiUI и из собственного CLI харнеса.

## Текущие ограничения

- Сборки для Windows не подписаны, пока для релизов не настроен сертификат подписи кода, а сборка обновляется сама, только если выпущена с ключом обновлений ([Выпуск релизов](docs/RELEASING.md)).
- Linux и macOS: контроль жизненного цикла нативных агентов не проверен, end-to-end стенд для Linux WebKit не реализован; сборки для macOS не нотаризованы.
- Автоматизации работают, только пока PiUI открыт.
- Шаг «Вызов модели» на Codex сохраняет собственные инструменты Codex внутри read-only sandbox; Pi и Claude Code выполняют вызов модели без инструментов. Одобрение MCP-инструмента Codex действует на один вызов, MCP-запросы в режиме URL отклоняются.
- Шаги-скрипты выполняют ваш код на этом компьютере с вашими правами; это не sandbox.
- Прежний интерфейс доступен из «Настройки → О программе» в этом релизе и будет удалён в следующем.
- Одновременная запись в одну сессию из PiUI и CLI харнеса не поддерживается.
- JavaScript расширений из папки проекта остаётся отключённым до завершения модели доверия и изоляции.

Точный статус: [состояние основы](docs/13_FOUNDATION_STATUS.md), [открытые риски](docs/12_OPEN_RISKS.md), [статус мультихарнесной реализации](docs/MULTI_HARNESS_IMPLEMENTATION.md) и [чеклист релиза](CHECKLIST_RELEASE.md); изменения — в [журнале изменений](CHANGELOG.md).

## Сборка из исходников

### Требования

- Git
- Node.js 22+
- pnpm 10.23+
- Rust 1.94.1 с `rustfmt` и `clippy`
- [платформенные зависимости Tauri 2](https://v2.tauri.app/start/prerequisites/)
- хотя бы один поддерживаемый харнес для живых чатов

### Сборка для разработки

```bash
git clone https://github.com/CrazyAngelm/PiUI.git
cd PiUI
pnpm install --frozen-lockfile
pnpm tauri dev
```

`pnpm --filter @piui/desktop dev` открывает интерфейс в браузере с in-memory хостом UI Lab, который никогда не запускает агентов; его сценарии описаны в [apps/desktop/README.md](apps/desktop/README.md).

### Релизная сборка

```bash
pnpm install --frozen-lockfile
pnpm repo:check
pnpm release:windows   # установщик NSIS и портативный exe в artifacts/
pnpm release:linux     # .deb и AppImage
pnpm release:macos     # универсальные .app и .dmg (экспериментально)
```

Без переменных подписи это неподписанные сборки, которые никогда не проверяют обновления. Подпись кода, подписанные обновления, теги и проверка описаны в [Выпуск релизов](docs/RELEASING.md).

## Проверки качества

```bash
pnpm repo:check
python tools/validate_spec.py
pnpm check
pnpm test
pnpm contract:test
pnpm build
pnpm test:smoke
pnpm test:e2e
pnpm perf:smoke
cargo fmt --all -- --check
cargo clippy --workspace --all-targets -- -D warnings
cargo test --workspace
```

`pnpm repo:check` также падает, если объявленные версии PiUI расходятся. `pnpm test:smoke` — статическая проверка исходников. `pnpm test:e2e` запускает реальный стенд Windows Tauri/WebView2 через feature-gated debug-only loopback driver и очистку фикстур вне Job. На Linux проверка по-прежнему явно завершается ошибкой: стенд WebKit ещё не реализован.

## Структура репозитория

```text
apps/desktop/               Tauri 2 host и интерфейс на Svelte 5
crates/piui-contracts/      Безопасные DTO host/UI и фикстуры
crates/piui-index/          Перестраиваемый SQLite-индекс и LF-only сканер сессий
crates/piui-runtime/        Мосты нативных харнесов, жизненный цикл и проекция потоков
crates/piui-orchestration/  Не зависящая от харнеса политика пайплайнов и координация запусков
crates/piui-platform/       Нативная идентичность и изоляция процессов
crates/piui-extensions/     Валидация манифестов расширений
contracts/                  Версионированные TypeScript-контракты
docs/                       Документация по продукту, архитектуре, безопасности и релизам
scripts/                    Проверки репозитория и инструменты релиза
spikes/                     Изолированные эксперименты и доказательства, не runtime-зависимости
```

## Участие в разработке и безопасность

Мы рады вкладу в проект. Перед открытием pull request прочитайте [CONTRIBUTING.md](CONTRIBUTING.md) и [AGENTS.md](AGENTS.md). Изменения IPC-контрактов требуют повышения версии, проверок совместимости и обновления файлов в `contracts/`.

Об уязвимостях сообщайте приватно согласно [SECURITY.md](SECURITY.md). Никогда не публикуйте в issue учётные данные, промпты, файлы сессий или локальные пути файловой системы.
