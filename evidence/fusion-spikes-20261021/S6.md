# S6 - Structured facts available in raw native events (Claude Code / Codex / Pi)

Read-only spike. Versions inspected: codex-cli 0.163.0 (schema generated with
`codex app-server generate-ts` / `generate-json-schema`, output in the scratchpad dirs `cx-ts`, `cx-schema`),
Claude Code 2.1.302 (`sdk-tools.d.ts` shipped with the package + string inspection of `claude.exe` +
real transcript JSONL under `~/.claude/projects/D--Projects-PIUI`), Pi 0.85.1 (`docs/rpc.md`, `docs/json.md`,
`dist/core/tools/{bash,edit,write}.js`).
Bridge files: `crates/piui-runtime/bridge/{claude,codex,pi}.mjs` (line numbers below are in those files).
No model was run. Anything not seen in a schema, shipped source or a real transcript is marked UNVERIFIED.

Reliability legend: **native** = a typed field the harness itself emits; **heuristic** = parsed out of text or inferred;
**unavailable** = not in the stream.

## 0. Cross-cutting findings

1. Every adapter already sees the raw frame before projection, in one place per event class (section 4).
   The loss happens in `putItem` / `putBlock` / `finishTool` and friends: they build a `NativeBlock`
   (id, kind, label, status, text, title, toolName) and drop the raw object.
2. Block ids are NOT native ids: Claude and Pi hash them (`toolBlockId` = `opaque("claude-tool", tool_use_id)`;
   `opaque("pi-tool", toolCallId)` at pi.mjs:418). Codex uses the native `item.id` directly (codex.mjs:335-340).
   A receipt must carry the adapter-private native id (and the block id for UI cross-reference).
3. Status collapse: Codex `mapStatus` (codex.mjs:182-187) maps `declined` to `interrupted`; "denied by user" and
   "interrupted" become the same block status. The raw `item.status` is the only place the difference exists.
   Claude `finishTool` (claude.mjs:681-693) reduces everything to the `is_error` boolean.
4. Subagent / child-thread work is dropped before it reaches blocks: Claude ignores every frame with
   `parent_tool_use_id != null` (claude.mjs:694, 742, 775); Codex drops item notifications whose
   `threadId !== nativeId` (codex.mjs:936); Pi has no subagents. Files changed by a Claude/Codex subagent are
   invisible to a receipt built at these seams unless the filters are relaxed.
5. Shell-based edits (sed -i, python, redirects, git checkout) are invisible as file edits in all three harnesses,
   with one exception: Claude Code 2.1.302 attaches an undocumented `bashEditDiff` (files, hunks, `changedFiles`)
   to some Bash `tool_use_result` objects (580 of ~2800 Bash results in the local transcripts). It is NOT in the
   typed `BashOutput` in `sdk-tools.d.ts`, so treat it as unstable best-effort (heuristic).
   Codex `commandActions` only classifies read / listFiles / search / unknown - there is no "write" action.
6. The only reliable "what changed on disk" signal independent of harness is a host-side filesystem/git snapshot
   diff around the turn. Native events say what the agent attempted and what the harness reported.
7. Approvals only exist when the harness asks. Codex is started with `approvalPolicy:"never"` for permissionMode
   read-only / workspace-write / full-access (codex.mjs:1256-1262), so no approval requests are sent in those modes
   (a sandbox denial shows up as a failed command). Claude only emits `can_use_tool` when its permission rules do not
   already allow/deny the call; auto-allowed calls produce no approval event. Pi has no built-in permission system
   (docs/security.md); approvals are extension `confirm` dialogs only.
   So "approval absent" must never be read as "denied". "Granted/denied" is also a HOST fact: it is the
   `respond({requestId, decision})` call in each adapter (codex.mjs:1615, claude.mjs:1644, pi.mjs:635).
8. Wall-clock: Codex gives `durationMs` natively; Claude/Pi give none on tool events, so the adapter must stamp
   start/end itself.

Codex gaps / impossibilities:
- Shell-run writes arrive as `commandExecution` only; no file path list; `commandActions` has no write type.
- UNVERIFIED whether an `apply_patch` invoked inside a shell command is promoted to `fileChange` in 0.163.0.
- The adapter reads `params.availableDecisions` (codex.mjs:383) but that field is NOT in the 0.163.0 `CommandExecutionRequestApprovalParams` schema, so the default four decisions are used. Not needed for receipts; noted as drift.
- Child-thread items are filtered at codex.mjs:936; `collabAgentToolCall` / `subAgentActivity` items exist in the schema but only get a generic tool block.
- Durable cross-check: `thread/read`, `thread/turns/list`, `thread/items/list` exist in `ClientRequest` and would return the typed items after the fact (not used by the adapter; payload UNVERIFIED).

Claude gaps / impossibilities:
- Exit code as a typed value is impossible; only the `Exit code N` text prefix. Refusal/denial/hook-block vs "command exited non-zero" is distinguishable by text only.
- Stream-start `input` is empty; the receipt must read the input from the final `assistant` message.
- Subagent (`Task`/`Agent`) inner tool calls are filtered (694/742/775); only the parent `Agent` tool_result is seen.

## 5. Proposed minimal typed receipt schema

```ts
type ReceiptSource = "native" | "heuristic";     // missing field = unavailable

interface FactBase {
  harness: "codex" | "claude-code" | "pi";
  nativeCallId: string;          // item.id | tool_use_id | toolCallId (adapter-private, never to the WebView)
  blockId: string;               // NativeBlock id for UI cross-reference
  turnRef?: string;              // codex turnId; claude/pi: adapter turn serial
  startedAtMs?: number;          // codex native; others adapter-stamped (heuristic)
  endedAtMs?: number;
  sidechain?: boolean;           // only if the parent_tool_use_id / child-thread filters are relaxed
}

type FileOp = "create" | "update" | "delete" | "rename" | "unknown";

interface FileFact extends FactBase {
  kind: "file";
  tool: string;                  // "fileChange" | "Edit" | "Write" | "NotebookEdit" | "edit" | "write" | MCP name
  changes: Array<{
    path: string;                // as reported (absolute for claude/codex; may be relative for pi)
    op: FileOp;
    movedTo?: string;            // codex move_path
    additions?: number;          // claude gitDiff/structuredPatch; codex derivable from diff; pi from details.patch
    deletions?: number;
    patch?: unknown;             // optional, bounded unified diff
  }>;
  outcome: "applied" | "failed" | "declined" | "interrupted" | "staged" | "unknown";
  outcomeSource: ReceiptSource;  // codex: native status; claude: is_error + staged native; pi: isError native
  errorText?: unknown;           // bounded
}

interface ShellFact extends FactBase {
  kind: "shell";
  tool: string;                  // "commandExecution" | "Bash" | "PowerShell" | "bash"
  command: string;               // full text, not the 200-char title
  cwd?: unknown;
  outcome: "ok" | "nonzero-exit" | "failed" | "declined" | "interrupted" | "timeout" | "backgrounded" | "unknown";
  exitCode?: number | null;      // codex native; claude/pi parsed from text
  exitCodeSource?: ReceiptSource;
  durationMs?: number | null;    // codex native, others adapter-stamped
  stdout?: unknown;              // claude tool_use_result.stdout; codex/pi: merged output only
  stderr?: unknown;
  outputTruncated?: boolean;
  shellWrites?: string[];        // claude bashEditDiff.changedFiles when present (heuristic)
  gitOperation?: unknown;        // claude BashOutput.gitOperation when present
}

interface ApprovalFact extends FactBase {
  kind: "approval";
  approvalId: string;            // adapter approval id
  nativeRequestId: string;       // JSON-RPC id | control request_id | extension_ui id
  relatesToCallId?: string;      // codex params.itemId; claude request.tool_use_id; pi: unavailable
  action: "command" | "file-change" | "permission" | "input" | "mcp";
  subject?: unknown;             // command text / paths / tool name shown to the user
  requestedAtMs: number;         // adapter clock
  decision?: "approve-once" | "approve-session" | "deny" | "cancel" | "withdrawn" | "timeout";
  decisionBy?: "host-broker" | "user" | "policy";   // who called respond(); host fact
  decidedAtMs?: number;
  nativeConfirmation?: "serverRequest/resolved" | "control_cancel_request" | "item-declined" | "none";
}

type Fact = FileFact | ShellFact | ApprovalFact;

interface TurnReceipt {
  turnRef: string;
  facts: Fact[];
  coverage: {                                   // so the broker never over-claims
    fileTools: "complete" | "partial";          // partial when sidechain work was filtered or MCP tools were used
    shellWritesVisible: false;                  // natively unenumerable (Claude bashEditDiff is best-effort only)
    approvals: "complete-for-asked" | "none-possible";   // codex approvalPolicy never => none-possible
  };
  workspaceDiff?: unknown;                      // independent host fs/git evidence, not native
}
```

## 6. What is impossible natively

- Claude Code and Pi: typed Bash exit code (text only). Codex has it.
- Claude/Pi tool duration (Codex only).
- Separate stdout/stderr for Codex (merged `aggregatedOutput`) and Pi (single text); Claude has both in `tool_use_result`.
- A native list of files modified by shell commands in Codex and Pi; Claude only via undocumented `bashEditDiff`.
- Pi approvals linked to a tool call; any Pi approval for built-in tools.
- "Auto-denied by policy": Codex under `approvalPolicy:"never"` shows only a failed item; Claude rule-based denials show only text plus the final `permission_denials`.
- Telling "interrupted" from "declined" from the projected Codex block without raw `item.status`.
