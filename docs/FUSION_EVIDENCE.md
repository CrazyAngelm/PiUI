# Fusion — доказательства Ф0 (спайки S1–S11)

Дата: 21 октября 2026. Основание: план `docs/PLAN_FUSION_2026-10-21_RU.md`, Ф0.
Пробники: `scripts/fusion-spikes/` (запуск из корня репозитория, вывод в
`target/fusion-spikes/`). Подробные статические отчёты и журналы прогонов:
`evidence/fusion-spikes-20261021/`. Код PiUI в ходе спайков не менялся.

## Как проверяли

- **Синтетика** (бесплатно, детерминированно): установленные Codex 0.163.0 и Pi через
  собственные адаптеры PiUI (`crates/piui-runtime/bridge/*.mjs`), изолированный дом и
  локальный провайдер Responses, который сам «вызывает» нужные инструменты.
- **Реальные прогоны** (подписка пользователя): Claude Code 2.1.302, модель `haiku`,
  усилие `low`, крошечные промпты, всего 11 ходов; Codex — 2 хода `gpt-6-luna`.
  Адаптер Claude сам чистит окружение от API-ключей (ADR-029). Во время прогонов
  Claude Code предупредил, что недельный лимит подписки близок (сброс 2026-10-24),
  поэтому платные ходы сведены к минимуму.
- **Статика**: три субагента (только чтение) по коду, бинарникам и сгенерированной
  схеме протокола `codex app-server`. Их отчёты лежат в `evidence/` целиком.
- Codex 0.163.0 новее проверенного адаптером потолка 0.158 (см. E1), поэтому пробники
  импортируют копию адаптера с поднятым только этим потолком (`target/`, не репозиторий).

## S1. Длинные вызовы host-инструмента

Метод: `boardRequest` отвечает через заданную задержку; модель вызывает `board` один раз.

| Харнес | Задержка | Итог |
|---|---|---|
| Codex 0.163 (dynamic tool) | 3 / 130 / 660 с | Ответ доставлен, ход `succeeded` |
| Codex | 60 с, прерывание на 8 с | `signal` отменил ожидание хоста сразу, ход `interrupted` |
| Claude Code 2.1.302 (HTTP MCP) | 3 с | Ответ доставлен |
| Claude Code | 70 / 330 / 660 с | Через ~64 с модель получила «The operation timed out.», ход `succeeded`; запрос к хосту завершился позже, ответ ушёл в никуда |
| Claude Code, `MCP_TOOL_TIMEOUT=600000` | 200 с | Ответ доставлен, ход `succeeded` |
| Claude Code | 60 с, прерывание на 15 с | Ход `interrupted` сразу, но запрос к хосту не отменён (у Claude нет `signal`) |

Выводы:

1. Предел порции для Claude Code без настройки — меньше 60 с. Адаптер может задать
   `MCP_TOOL_TIMEOUT` в окружении процесса Claude (это не учётные данные), тогда предел
   задаёт хост. Значение — параметр, подтверждаемый тестом версии Claude Code.
2. Отмена ожидания не равна отмене работы, и для Claude хост об отмене **не узнаёт**.
   Поэтому брокер сам ограничивает ожидание порцией и не считает отчёт доставленным
   через результат инструмента, если ответ ушёл после проверенного срока транспорта.
3. Не проверено: Hermes, ACP, Prime (в v1 не допущены).

## S2. Связь раунда, хода и ответа

Синтетика, одна постоянная сессия на харнес, восемь сценариев подряд.

| Сценарий | Codex | Pi |
|---|---|---|
| R1 обычный ход | 1 завершение, ответ R1 | то же |
| R2 steer во время ответа | Принят; второй запрос к модели в том же ходе; 1 завершение | то же |
| R3 steer во время вызова инструмента | Принят; уходит вместе с результатом инструмента; 1 завершение | — |
| R4 steer после завершения | `no-active-turn` | то же |
| R5 ход без ответа | `succeeded`, нового ответа нет, «последний ответ» — от R3 | то же (от R2) |
| R6 ошибка провайдера (HTTP 400) | `failed` | `failed` |
| R7 follow-up во время хода | `turn-active` | Принят и **слит** с текущим ходом: 1 завершение, ответ уже на follow-up |
| R8 прерывание, затем новый ход | `interrupted`, затем `succeeded` | то же |

Codex сам защищает steer: `turn/steer` требует `expectedTurnId`. У Claude Code (по коду
и тесту `claude.test.mjs:585`) неподхваченный steer исполняется вторым нативным запуском
в том же принятом ходе, а follow-up во время хода уходит в нативную очередь с
`priority: later` как отдельный ход и после записи не отзывается.

## S3. Доставка простаивающему ведущему

| Харнес | Follow-up в простое | Follow-up во время хода |
|---|---|---|
| Codex | Начинает ход (синтетика) | `turn-active` |
| Claude Code | Начинает ход сразу (код адаптера) | Нативная очередь `later`, отзыва нет |
| Pi | Принят, но ход **не начинается**; адаптер уже засчитал ход (`admittedTurns`) | Сливается с текущим ходом |

## S5. Права напарника

- **Claude Code `workspace-write` (`acceptEdits`)**: запись файла прошла без вопроса. Команда
  оболочки (на Windows — PowerShell) пришла как одобрение «Run command» с вариантами
  только `deny/cancel` (`claude.mjs:1048`). Значит, такой напарник не выполнит команды
  проверки из брифа, если их не разрешают собственные настройки Claude пользователя.
  Ещё: напарник ответил по-русски — глобальный `CLAUDE.md` пользователя действует и на
  него, поэтому строка `STATUS` и разделы отчёта должны быть явно закреплены в
  инструкциях напарника, а разбор — устойчив.
- **Codex `workspace-write`** (синтетика):
  - Без `[windows] sandbox` все четыре команды отклонены «blocked by policy».
  - С `sandbox = "unelevated"` (так настроено у пользователя): `node --version` и запись
    внутри проекта прошли, запись вне проекта — `EPERM`.
  - `process.exit(3)` вернулся как код 1: обёртка `powershell -Command` сводит коды к
    0/1.
  - Одобрений не было: адаптер ставит `approvalPolicy: never`.

## Решения по итогам Ф0

1. Порция ожидания = min(проверенный срок транспорта, параметр). Для Claude-ведущего
   адаптер задаёт `MCP_TOOL_TIMEOUT`; без этого предел порции — 45 с.
2. Отчёт, ответ на который ушёл после срока транспорта, не считается доставленным через
   инструмент — он идёт авто-доставкой.
3. Раунды — только через очередь хоста и `prompt` в простое; нативный follow-up для раундов
   не используется (Pi сливает и не стартует).
4. Claude-напарник в v1 — только `full-access`. Codex-напарник в `workspace-write` — только
   при проверенной Windows-песочнице. Режим «запись в папку + явный список команд» —
   отдельный ADR.
5. Codex-ведущий: `piui.sidekick` регистрируется при `thread/start` Fusion-чата и работает
   после возобновления; мост принимает такие вызовы и в возобновлённом треде.
6. Строгий ведущий через `plan`/read-only исключён.
7. Квитанции исполнения и идентичность вызова — по схемам из S6 и S10.
8. Повторное открытие напарника — по схеме S11 (`SidekickStore`, `prepare_sidekick_open`).

## Не проверено

- Hermes, ACP, Prime (в v1 не допущены).
- Кэш Codex после пауз длиннее 2 минут; TTL Claude ровно 1 час.
- Повтор MCP-вызова Claude Code с тем же `toolUseId` (по строкам бинарника, не вживую).
- Поведение под Linux.
