# Nano: общий интерфейс вебки и desktop

Изменения находятся в отдельных ветках `codex/nano-unification` двух репозиториев.
Установленная программа и рабочий сайт обновляются отдельным выпуском.
Реализация всех этапов завершена. Каждый ключевой этап прошёл четыре независимых
read-only ревью GPT-6.1 Sol с max reasoning; подтверждённые замечания исправлены.
Результаты проверок записаны в [журнале реализации](NANO_UNIFICATION.md).

## Как это выглядит

В desktop есть два места работы: **This computer** и **Nano Cloud**. На компьютере
человек работает с установленными агентами, своими проектами и файлами. В Cloud
он работает с серверными диалогами и возможностями Nano. Переключение места само
по себе не переносит историю, не отправляет локальные файлы на сервер и не
открывает облачному агенту доступ к компьютеру.

По умолчанию desktop использует изумрудный стиль Nano. Можно выбрать Chaos,
светлое, тёмное или системное оформление. Выбор стиля и светлой/тёмной схемы
независим. Плагины могут задавать палитру, форму элементов, декор и шрифтовой
стиль через декларативный API. Их собственные панели сохраняют действующую
изоляцию и разрешения.

Без подписки desktop остаётся полноценной оболочкой для доступных локальных
агентов, пайплайнов и плагинов. Недоступные серверные аватары не оставляют пустые
места. Их ресурсы выдаёт сервер при наличии доступа; библиотека аватаров не
устанавливается на компьютер для автономного использования.

## Что стало общим

- Дизайн-токены и основные правила оформления.
- Редактор графов и контракт переносимого пайплайна; серверное выполнение
  использует общую Rust-логику переходов и отдельного серверного владельца.
- Представление сообщений, шагов агента, разрешений, файлов и медиа, поиск и
  загрузка истории. Действия сообщения выполняет его текущий владелец.
- Оформление поля ввода, рост по высоте и клавиатурное поведение. Черновики,
  вложения и отправка остаются в существующих контроллерах.

В вебке общий интерфейс включается по умолчанию. Личные, временные, гостевые,
служебные, групповые и голосовые диалоги сохраняют свои правила. Аватары, даты,
подписи авторов, документы и их версии, просмотр экрана и голосовое управление
используют существующие веб-компоненты. При сбое загрузки общего модуля остаётся
рабочий запасной интерфейс. Печать собирает полную отдельную копию представления,
не переключая живой чат и не трогая черновик.

## Что остаётся отдельным

Desktop владеет доступом к ОС, локальными файлами, установленными harness,
их разрешениями, очередями и родными форматами истории. Вебка владеет аккаунтами,
подпиской, серверными файлами, облачными агентами и соответствующими сервисами.
Групповые раунды и голосовая связь сохраняют свои серверные протоколы.

Веб-сервер продолжает работать на .NET. Rust используется там, где уже есть
общая логика пайплайнов и нативный host. Общие Svelte-компоненты подключаются
через явные адаптеры. История не конвертируется в новый универсальный формат.

## Границы и риски

Общий интерфейс уменьшает дублирование, но новая возможность всё равно должна
быть поддержана соответствующим владельцем. Например, локальный инструмент ОС
требует нативной реализации, а управление подпиской — серверной. Недоступная
возможность не должна выглядеть как разрешённая только потому, что есть кнопка.

Браузерные проверки используют настоящие компоненты и обработчики с тестовыми
API, событиями и медиа. Проверены настоящий Tauri/WebView2, обычный и безопасный
режимы. Последнее исправление подтверждения отправки дополнительно прошло
19 модульных и семь браузерных проверок с тестовым host; нативный exe для этой
правки не пересобирался. Финальные проверки сервера: 74/74, общих компонентов:
29/29, отдельный браузерный сценарий границ владельца и шесть групп сценариев
скомпилированной вебки. Проверки не доказывают платные ответы провайдеров,
работу физического микрофона или готовность выпуска для Linux.

Консультация Opus 5.5 была запрошена через подписочный Claude CLI, но авторизация
оказалась недоступна до обращения к модели. Советы Opus не использовались;
результаты независимых Sol-ревью сохранены.

Изменения подготовлены для последующего объединения веток и обычного выпуска.
Перед выпуском остаются проверки конкретной среды развёртывания и установщика;
эта задача не изменяет production и установленную копию приложения.
